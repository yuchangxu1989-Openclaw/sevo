## FR-11：Proactive Clarification（主动澄清机制）

### FR-11.1 Spec 阶段澄清

#### TC-11-01
- 关联 AC：AC-4.41
- 前置条件：Spec Package 正在编写，内容中存在验收标准缺失、边界未定义等模糊信号
- 测试步骤：
  1. 提交含模糊点的 Spec 内容（如 FR 无验收标准、术语未定义）
  2. 触发 Spec 产出流程
  3. 检查产出前的澄清记录
- 预期结果：所有被检测到的模糊点都已生成对应澄清问题，或被显式标注为已知风险；无遗漏的未处理模糊点

#### TC-11-02
- 关联 AC：AC-4.42
- 前置条件：系统检测到模糊点并生成澄清问题
- 测试步骤：
  1. 触发澄清流程
  2. 检查每条澄清问题的结构
- 预期结果：每条澄清问题包含：类型标签（纠偏/方法/决策/边界/经验/元认知）、影响范围描述、上下文引用（指向 Spec 中的具体位置），不是孤立无上下文的提问

#### TC-11-03
- 关联 AC：AC-4.43
- 前置条件：澄清问题已获得回复，收敛结论已产出
- 测试步骤：
  1. 回复澄清问题
  2. 检查 Spec Package 文件内容
  3. 检查对话记录和临时文件
- 预期结果：收敛结论直接写入 Spec Package 对应位置（FR 描述、AC、约束条件等），不仅留在对话或临时文件中

#### TC-11-04
- 关联 AC：AC-4.44
- 前置条件：多种类型的澄清已收敛
- 测试步骤：
  1. 产出纠偏类澄清结论，检查沉淀位置
  2. 产出决策类澄清结论，检查沉淀位置
  3. 产出边界类澄清结论，检查沉淀位置
  4. 产出方法类澄清结论，检查沉淀位置
  5. 产出经验类澄清结论，检查沉淀位置
  6. 产出元认知类澄清结论，检查沉淀位置
- 预期结果：纠偏→事实知识、决策→ADR 候选、边界→约束条件、方法→方法论记录、经验→经验库/lessons learned、元认知→方法论/流程改进建议，各归其位

### FR-11.2 Contract 阶段澄清

#### TC-11-05
- 关联 AC：AC-4.45
- 前置条件：Contract Package 正在编写，存在接口未定义、数据流不明等技术模糊点
- 测试步骤：
  1. 提交含技术模糊点的 Contract 内容
  2. 触发 Contract 产出流程
  3. 检查产出前的澄清记录
- 预期结果：所有被检测到的技术模糊点都已澄清（有明确结论）或记录为待定风险（标注风险等级和后续处理计划）

#### TC-11-06
- 关联 AC：AC-4.46
- 前置条件：Contract 阶段检测到需求层面的模糊（非技术层面）
- 测试步骤：
  1. 在 Contract 中引入需求层面的歧义（如 FR 描述可多种理解）
  2. 观察系统处理方式
- 预期结果：需求层面的模糊上报给 Spec 来源方（用户或上游 Agent），不由架构阶段单方面假设或自行决定

#### TC-11-07
- 关联 AC：AC-4.47
- 前置条件：技术决策类澄清已收敛
- 测试步骤：
  1. 触发技术决策类澄清（如选择数据库方案）
  2. 收敛后检查 ADR 文件
- 预期结果：技术决策类澄清收敛后写入 ADR，ADR 包含替代方案和取舍理由，不只记录最终选择

#### TC-11-08
- 关联 AC：AC-4.48
- 前置条件：Spec 与 Contract 之间存在矛盾（如 Spec 要求同步处理，Contract 设计为异步）
- 测试步骤：
  1. 构造 Spec 与 Contract 的矛盾场景
  2. 在 Contract 阶段触发检测
- 预期结果：矛盾在 Contract 阶段被检测并消解（通过澄清流程确认以哪个为准），不流入 Implement 阶段

### FR-11.3 Implement 阶段澄清

#### TC-11-09
- 关联 AC：AC-4.49
- 前置条件：Task 描述不完整（缺少输入格式、边界条件等关键信息）
- 测试步骤：
  1. 派发描述不完整的 Task
  2. 观察执行者行为
- 预期结果：执行者主动提问请求补充信息，不基于猜测开发；提问内容指向具体缺失项

#### TC-11-10
- 关联 AC：AC-4.50
- 前置条件：实现过程中发现 Spec 与 Contract 存在矛盾
- 测试步骤：
  1. 构造 Spec 说"最多 5 个"、Contract 说"无上限"的矛盾
  2. 执行者进入实现阶段
- 预期结果：实现暂停，矛盾上报给上游（Spec 或 Contract 负责方），不自行决定以哪个为准

#### TC-11-11
- 关联 AC：AC-4.51
- 前置条件：实现过程中产生多个澄清问题
- 测试步骤：
  1. 触发多个澄清问题
  2. 检查每个问题的阻断级别标注
- 预期结果：每个澄清问题标注阻断级别；blocking 类问题等待回复后才继续；non-blocking 类问题附默认假设先行开发，回复后修正

#### TC-11-12
- 关联 AC：AC-4.52
- 前置条件：Implement 阶段澄清已收敛
- 测试步骤：
  1. 完成澄清并获得结论
  2. 检查对应工件内容
- 预期结果：澄清结论回写到对应工件（Task 描述、Spec Package 或 Contract Package），不只留在执行日志中

### FR-11.4 实现路径

#### TC-11-13
- 关联 AC：AC-4.53
- 前置条件：需要新增自定义模糊检测规则
- 测试步骤：
  1. 在配置文件中添加新的模糊检测规则（如"金额字段未指定币种"）
  2. 提交含该模糊信号的 Spec
  3. 观察是否触发澄清
- 预期结果：新规则生效，触发对应澄清问题；扩展过程不需要修改 Skill 源码，仅通过配置文件完成

#### TC-11-14
- 关联 AC：AC-4.54
- 前置条件：澄清流程已完成一轮完整的触发→提问→回复→收敛
- 测试步骤：
  1. 完成一轮澄清
  2. 检查 Ledger Entry 的证据链
- 预期结果：Ledger Entry 中包含完整澄清记录：触发点（哪个模糊信号）、问题（结构化澄清问题）、回复（来源方答复）、收敛结论（最终决定），可追溯完整链路

#### TC-11-15
- 关联 AC：AC-4.55
- 前置条件：不同 Agent 身份的执行者进入同一阶段
- 测试步骤：
  1. 用 Agent-A 进入 Spec 阶段，验证澄清能力可用
  2. 用 Agent-B（不同身份）进入 Spec 阶段，验证澄清能力可用
  3. 用 Agent-C 进入 Implement 阶段，验证澄清能力可用
- 预期结果：澄清机制不依赖特定 Agent 身份，任何执行者进入对应阶段都自动获得澄清能力，无需额外配置或权限授予
