# SEVO Web Dashboard 交互设计文档

OMP（OpenClaw ACP Agent）2026-05-30

## 1. 页面 / 流程概览

### 1.1 文档范围

本文只覆盖 SEVO Web Dashboard 中与流水线推进和质量闭环直接相关的核心页面：

- 流水线列表页：`/frs`
- 流水线创建 / 触发入口：在 `/frs` 首屏提供主按钮，可用抽屉或独立路由承载创建表单
- 流水线详情页：`/frs/[id]`
- 阶段状态相关视图：总览页 `/dashboard`、FR 详情中的阶段时间线与质量视图 `/frs/[id]/quality`
- 审计报告页：`/reviews`
- doctor 报告页：作为 Dashboard 内的系统诊断报告入口，承接 spec 中 `sevo:doctor` 结构化报告的查看需求

不在本文范围内的页面：登录、通知、项目矩阵、产物库、账本详情、设置页的具体交互。

### 1.2 目标用户

- 独立产品操盘者：要在最短时间看清哪条 FR 卡住、卡在什么阶段、下一步该点哪里。
- Agent 原生开发者：要快速查看当前流水线阶段、失败原因、重试和恢复入口。
- 质量与架构把关者：要集中查看审计问题、修复状态、复验结果。
- OpenClaw 环境管理者：要看 doctor 报告中的错误、警告、受影响范围和修复建议。

### 1.3 使用时机

- 用户进入 Dashboard 后先看全局健康和风险优先级。
- 用户进入 FR 列表筛选正在推进、等待门禁、失败待恢复的流水线。
- 用户打开某条 FR 的详情，理解当前阶段、已完成阶段、阻塞点和下一步。
- 用户进入质量视图或审计报告页，查看问题项、修复任务和复验结果。
- 用户发现运行异常或被系统提示不可继续推进时，打开 doctor 报告页定位 Errors / Warnings。

### 1.4 页面目标

- 总览页：5 秒内告诉用户“系统现在稳不稳，先处理哪三件事”。
- 流水线列表页：优先暴露异常、等待和推进中的 FR，不让用户淹没在已完成条目里。
- 流水线创建 / 触发入口：让用户在 Web 上选择项目、填写 FR 和终局目标，创建后直接看到流水线开始推进。
- 流水线详情页：把一条 FR 的当前状态、阶段轨迹、阻塞原因、恢复动作放在一个页面里讲清楚。
- 阶段状态视图：让用户知道真实编排阶段、并行支路、汇合点、回退链路和 4 个用户宏阶段当前分别处于什么状态。
- 审计报告页：让用户按严重等级处理问题，并看到修复和复验是否闭环。
- doctor 报告页：在系统层面明确“能不能继续推进”，Errors 大于 0 时给出阻断提醒和修复方向。

### 1.5 成功结果

用户不需要猜，不需要翻多个页面，就能回答五个问题：

- 哪条 FR 最值得先看
- 当前卡在哪个阶段
- 是门禁、澄清、失败还是 doctor 阻断
- 现在可执行的主动作是什么
- 做完后回到哪里继续确认结果

### 1.6 上游入口

- 登录后进入 `/dashboard`
- 侧边导航：总览、FR 流水线、风险与动作
- 风险队列卡片、状态卡片、列表项跳转
- 审计问题或 doctor 告警中的深链入口

### 1.7 下游去向

- 总览 → FR 列表 / 风险与动作 / 具体 FR 详情
- FR 列表 → FR 详情
- FR 详情 → 质量视图 / 时间线 / 审计问题 / 恢复动作
- 审计报告 → 修复任务追踪 / 对应 FR
- doctor 报告 → 对应受影响项目 / FR / 修复指引

## 2. 交互模式声明

### 2.1 整体模式

- 模式：表单式 + 状态驱动浏览式的混合模式
- 主输入方式：筛选、搜索、点击卡片、执行单步动作按钮
- 辅助输入方式：分页、标签切换、危险动作确认
- 不采用对话式输入作为主模式

### 2.2 采用原因

SEVO Dashboard 的核心任务是让用户快速判断当前状态并执行下一步动作。因此页面骨架必须以列表、状态卡、阶段轴、问题清单为主。对这类场景，结构化页面比聊天窗口更清楚，也更符合 spec 里“看清走到哪、卡在哪里、下一步是什么”的要求。

### 2.3 页面级模式声明

#### 总览页
- 模式：浏览式
- 核心输入：点击阶段卡、风险卡、统计卡跳转
- 目标：先判断，不在此页处理复杂细节

#### 流水线列表页
- 模式：筛选式列表 + 创建入口
- 核心输入：阶段筛选、项目筛选、关键词搜索、展开已完成、创建 / 触发流水线
- 目标：快速定位异常和在途 FR，也能从 Web 直接启动一条新流水线

#### 流水线详情页
- 模式：详情式 + 操作式
- 核心输入：暂停、恢复、重试、取消、放弃等单步动作
- 目标：一页内理解上下文并触发恢复动作

#### 审计报告页
- 模式：问题处理台
- 核心输入：严重等级筛选、问题 / 修复 / 复验三标签切换
- 目标：围绕问题闭环处理

#### doctor 报告页
- 模式：诊断报告式
- 核心输入：查看错误、警告、建议修复项，跳转受影响对象
- 目标：先判断“是否允许继续推进”，再进入具体修复点

## 3. 页面分区与信息结构

### 3.1 全局骨架

所有 Dashboard 页面共用统一骨架：

#### 区域 A：左侧主导航
- 用途：在总览、FR 流水线、风险与动作、产物库、项目之间切换
- 展示字段：页面名称、当前高亮项、产品标识 SEVO
- 可执行动作：点击进入对应模块
- 联动关系：当前路径决定高亮，帮助用户始终知道自己在哪个功能域

#### 区域 B：顶部工具区
- 用途：提供全局搜索、命令入口、通知入口、管理入口
- 展示字段：搜索框、快捷键提示、通知按钮
- 可执行动作：全局搜索、打开命令面板、查看通知
- 联动关系：搜索结果应跨 FR、产物、门禁、账本对象

#### 区域 C：页面标题区
- 用途：用一句人话告诉用户当前页要解决什么问题
- 展示字段：标题、描述、右侧摘要动作区
- 可执行动作：跳转相关页面或显示全局摘要
- 联动关系：当前页最重要的判断结果要放在这里，不要藏在内容区深处

### 3.2 总览页 `/dashboard`

#### 区域 A：System Call 摘要卡
- 用途：一句话总结系统是否健康
- 展示字段：健康度、完成率、总 FR 数、推进中数量、失败数量、摘要句
- 可执行动作：无直接写操作，仅作为判断入口
- 联动关系：摘要句要和风险数、失败数一致

#### 区域 B：真实阶段流水线卡阵
- 用途：从全局看真实编排阶段、并行支路和汇合点是否拥堵
- 展示字段：阶段名称、简称、数量、是否需处理、是否并行组、是否回退修复轮次
- 可执行动作：点击阶段进入带阶段筛选的 FR 列表
- 联动关系：数量来自宏阶段分布拆分；高风险阶段要有明显提示

#### 区域 C：风险队列 Top 3
- 用途：把当前最该处理的动作排在前面
- 展示字段：标题、FR 编号、等待时长、动作按钮文案
- 可执行动作：进入门禁页、澄清页或 FR 恢复页
- 联动关系：和“风险与动作”页口径一致

#### 区域 D：运行指标卡
- 用途：用三个数字暴露失败、门禁等待、进行中
- 展示字段：失败待恢复数、门禁等待数、正在推进数
- 可执行动作：点卡跳转到对应筛选页
- 联动关系：作为总览页的二级入口，不重复展示细节

### 3.3 流水线列表页 `/frs`

#### 区域 A：Web 创建 / 触发入口
- 用途：承接 spec 中“触发流水线 → 看到状态推进”的 Web 主操作
- 展示字段：主按钮“创建流水线”、当前 doctor 是否阻断、可用项目数、活跃流水线限制提示
- 可执行动作：打开创建表单、选择 Project、填写 FR 描述、填写终局目标、选择入口阶段（默认从 Spec 开始）、提交创建
- 联动关系：提交成功后创建 Pipeline，直接跳转到 `/frs/[id]`，详情页首屏显示 Pipeline Create 已完成、Specify / Spec 阶段已进入 pending 或 running；提交失败时保留表单内容并显示失败原因
- 禁用规则：doctor Errors > 0 时，“创建流水线 / 触发推进 / 从中途阶段重入”全部禁用，只允许查看诊断和跳转修复对象

#### 区域 B：状态摘要卡
- 用途：先显示当前筛选集合的 FR 数量、需关注数量、已完成折叠数量
- 展示字段：当前筛选 FR、异常 / 等待 / 推进中、已完成折叠
- 可执行动作：无
- 联动关系：为列表阅读建立预期

#### 区域 C：阶段筛选标签
- 用途：按 4 个用户宏阶段筛选
- 展示字段：全部阶段、需求澄清、方案规划、执行落地、质量复核
- 可执行动作：切换筛选
- 联动关系：切换后重置分页

#### 区域 D：组合筛选条
- 用途：按项目、关键词、完成态做进一步收窄
- 展示字段：项目下拉框、搜索框、展开 / 隐藏已完成按钮
- 可执行动作：项目筛选、模糊搜索、展开已完成
- 联动关系：搜索输入 300ms 防抖；已完成默认折叠

#### 区域 E：FR 列表
- 用途：以卡片形式展示每条 FR 当前阶段和风险状态
- 展示字段：宏阶段标签、流水线类型、状态标签、风险标签、标题、FR 编号、当前编排阶段、更新时间
- 可执行动作：点击进入 FR 详情
- 联动关系：列表排序优先保留异常、等待和推进中的条目；已完成单独折叠

#### 区域 F：分页区
- 用途：切换长列表页码
- 展示字段：当前页、总页数、总条数
- 可执行动作：上一页、下一页、指定页
- 联动关系：筛选变化后回到第一页

### 3.4 流水线详情页 `/frs/[id]`

#### 区域 A：返回与标题区
- 用途：返回列表，同时显示 FR 标题和编号
- 展示字段：返回按钮、FR 标题、FR 编号
- 可执行动作：返回列表
- 联动关系：保持用户不会在深页迷路

#### 区域 B：状态摘要卡
- 用途：用 5 秒摘要解释当前 FR 现在是什么情况
- 展示字段：当前宏阶段、Pipeline 状态、当前编排阶段、失败阶段或阻塞阶段、人话摘要
- 可执行动作：无
- 联动关系：摘要必须与时间线状态一致

#### 区域 C：关键指标卡
- 用途：把“当前负责人、已耗时、下一步”放在同屏
- 展示字段：负责人、已耗时、下一步建议
- 可执行动作：无
- 联动关系：下一步建议决定下方动作区的优先级

#### 区域 D：快捷视图区
- 用途：把质量视图、时间线、产物、全景等常用页面做成捷径
- 展示字段：入口标题、解释文案
- 可执行动作：跳转子页
- 联动关系：避免用户在详情页里滚很久找入口

#### 区域 E：动作区
- 用途：执行暂停、恢复、重试、取消、放弃等动作
- 展示字段：按钮、风险提示、动作错误反馈、doctor 阻断提示
- 可执行动作：单步状态操作
- 联动关系：动作成功后当前页就地刷新，不要求用户手动返回列表确认
- doctor 联动：doctor Errors > 0 时，所有会推进 Pipeline 的动作禁用，动作区顶部显示“当前受系统诊断阻断”，并提供跳转 doctor 报告页的入口

#### 区域 F：阶段时间线
- 用途：展示真实编排阶段的顺序、并行支路、汇合点、回退链路、尝试次数、产物数量、阻塞信息
- 展示字段：阶段名、状态、开始时间、完成时间、耗时、attempt、blockers、并行组、汇合条件、跳过原因
- 可执行动作：查看详情、进入关联子页
- 联动关系：当前阶段需突出；失败和阻塞需有原因入口；Review fail 自动回退到 Implement 时，时间线必须显示回退箭头和新一轮 Implement 修复任务

#### 区域 G：Review Fix Loop 卡片
- 用途：把审计失败后的自动闭环摆在详情页首屏可见范围内
- 展示字段：当前 review-fix retry 计数、最大重试次数、上一轮 Implement 执行者、当前修复执行者、是否已换人、最后审计结论、最后复验结论
- 可执行动作：查看阻断 Finding、查看自动生成的 Fix Task、查看复验结果
- 联动关系：Review 结论为 FAIL 或 CONDITIONAL_PASS 时自动出现；Review PASS 后折叠为历史记录，但时间线保留事件节点

### 3.5 阶段状态相关视图

#### 总览阶段卡阵
- 用途：看全局拥堵
- 颗粒度：全局阶段分布

#### FR 详情时间线
- 用途：看单条 FR 在真实编排阶段上的轨迹，包含并行阶段、汇合点、跳过原因和回退链路
- 颗粒度：单 FR 全链路

#### 质量视图 `/frs/[id]/quality`
- 用途：聚焦 Review、Smoke Test、UX Acceptance、PM Commercial Review、Regression、Verify、Post-Release Validation 等质量阶段
- 展示字段：质量得分、测试覆盖率、审计状态、Smoke 状态、UX 验收状态、商用评审状态、回归状态、验证状态、终局差距状态、问题列表
- 可执行动作：返回 FR 详情；后续可深链到问题项
- 联动关系：该页是“质量复核宏阶段”的专门展开页

### 3.6 审计报告页 `/reviews`

#### 区域 A：摘要指标卡
- 用途：先判断问题规模
- 展示字段：P0 待处理、P1 待处理、修复进行中、复验通过率
- 可执行动作：无
- 联动关系：与下方筛选和列表口径一致

#### 区域 B：严重等级筛选
- 用途：按 P0-P3 过滤
- 展示字段：全部、P0、P1、P2、P3
- 可执行动作：点击筛选
- 联动关系：切换后影响问题、修复、复验三类内容

#### 区域 C：标签切换
- 用途：在评审问题、修复任务、复验结果三种视角间切换
- 展示字段：标签名称、数量
- 可执行动作：切换标签
- 联动关系：三类数据是一个问题闭环的不同阶段，不应拆到完全无关的页面里

#### 区域 D：内容列表
- 用途：逐项展示问题 / 修复 / 复验细节
- 展示字段：严重等级、状态、描述、对应 FR、对应产物、责任信息
- 可执行动作：进入关联 FR 或定位修复对象
- 联动关系：问题状态变化后，同步反映到修复与复验列表

### 3.7 doctor 报告页

#### 区域 A：运行许可判断区
- 用途：先明确当前是否允许继续推进流水线
- 展示字段：Errors 数、Warnings 数、阻断结论、最近检查时间
- 可执行动作：刷新报告
- 联动关系：Errors > 0 时整页进入阻断视觉状态

#### 区域 B：错误列表
- 用途：展示必须先修的阻断项
- 展示字段：错误标题、影响范围、受影响项目、建议修复动作、证据摘要
- 可执行动作：跳转受影响对象
- 联动关系：错误项按严重程度和影响范围排序

#### 区域 C：警告列表
- 用途：展示非阻断但需要关注的问题
- 展示字段：警告标题、说明、建议处理时机
- 可执行动作：跳转关联页
- 联动关系：警告不应和错误混在一个列表里

#### 区域 D：报告说明区
- 用途：解释本次报告来源于 `sevo:doctor` 结构化输出
- 展示字段：数据来源、检查范围、提示文案
- 可执行动作：无
- 联动关系：帮助用户理解为什么系统说“不能继续”

## 4. 核心操作流

### 4.0 Web 端创建并触发流水线

1. 用户进入 `/frs`，点击“创建流水线”。
2. 系统先检查 doctor 阻断态；Errors > 0 时不打开可提交表单，直接提示先处理系统诊断错误。
3. doctor 允许推进时，用户选择 Project，填写 FR 描述和一句话终局目标。
4. 用户保持默认入口阶段“从 Spec 开始”，也可以选择从已允许的中途阶段重入；中途重入时，页面说明前置阶段会按状态标记为 passed 或 skipped，后续终局链仍会自动跑完。
5. 用户提交后，按钮进入 loading，表单不可重复提交。
6. 创建成功后，系统创建 Pipeline，生成 Stage Queue，并跳转到详情页。
7. 详情页首屏显示 Pipeline Create 已完成、当前进入的 Stage、预计门禁列表、进度摘要和“后台会继续推进”的提示。
8. 如果创建失败，表单保留用户输入，错误文案说明是项目不存在、已有 active 流水线、终局目标缺失、doctor 阻断，还是系统请求失败。

### 4.1 从总览进入处理闭环

1. 用户进入总览页。
2. 系统立即显示一句话健康摘要、真实阶段卡阵和风险队列 Top 3。
3. 用户判断是先处理失败、门禁还是澄清。
4. 用户点击风险项进入对应页面。
5. 处理完成后回到总览，确认风险数量是否下降。

### 4.2 从流水线列表定位某条 FR

1. 用户进入 FR 流水线页。
2. 系统默认优先展示异常、等待和推进中的 FR，已完成折叠。
3. 用户通过宏阶段标签、项目筛选或关键词定位目标 FR。
4. 用户点击某条卡片进入详情页。
5. 成功后在详情页看到当前阶段、阻塞点和主动作。
6. 如果筛选后为空，系统明确告诉用户为什么空，并给出清空筛选或展开已完成的动作。

### 4.3 在 FR 详情页判断并执行恢复动作

1. 用户进入 FR 详情页。
2. 系统在首屏展示 5 秒摘要：当前状态、失败阶段或阻塞阶段、下一步建议。
3. 用户先看时间线和质量视图入口，再决定是否点击暂停、恢复、重试、取消或放弃。
4. 用户执行动作后，按钮进入 loading 并禁用，页面保留当前上下文不跳转。
5. 成功时系统刷新详情数据，让状态、阶段、摘要同步变化。
6. 失败时在动作区显示错误文案，原页面上下文保留，用户可重试。

### 4.4 查看阶段状态

1. 用户从总览页点击某个阶段卡，或在详情页查看时间线。
2. 系统显示该阶段相关 FR，或显示单 FR 的阶段序列。
3. 用户通过状态颜色、图标和文案判断阶段处于待开始、进行中、阻塞、待澄清、通过、失败还是跳过。
4. 若阶段失败或阻塞，用户能看到原因摘要和下一跳入口。

### 4.5 审计失败自动回退闭环

1. Review 阶段返回 PASS 时，Pipeline 继续进入 Smoke Test 和后续阶段。
2. Review 阶段返回 FAIL 或 CONDITIONAL_PASS，且存在阻断 Finding 时，详情页和审计页同步显示“Review 未通过，已自动回退到 Implement 修复”。
3. 系统自动生成 Fix Task，关联审计报告全文、阻断问题清单、关联 FR/AC、失败证据、上一轮实现摘要和允许修改范围。
4. 时间线追加 `reviewFailed` 和 `implementRetryStarted` 事件，Review 节点显示 blocked，Implement 节点进入新一轮 running。
5. 修复完成后，时间线追加 `implementRetryCompleted`，系统自动重新进入 Review，并追加 `reviewRetried` 事件。
6. Review PASS 后，Finding 关闭，Fix Task 标记完成，时间线追加 `reviewPassed`，流水线继续推进 Smoke Test、UX Acceptance、PM Commercial Review、Regression、Commercialization Gate、Deploy、Verify、README 更新、发布、Post-Release Validation 和 Ledger。
7. 达到最大自动重试次数仍未通过时，Pipeline 暂停在 Review Fix 状态，详情页显示 `retryLimitReached`、已尝试轮次、最后审计结论和可选处理方式。
8. 若无法换不同 Implement Agent，Pipeline 暂停，修复策略卡说明“可用开发 Agent 不足，等待补充 Agent 或授权继续使用同一 Agent”。

### 4.6 doctor 报告处理流

1. 用户收到系统提示或主动进入 doctor 报告页。
2. 系统先显示“是否允许继续推进”的结论。
3. 如果 Errors > 0，系统把错误列表放到首屏，明确提示禁止继续推进或重启 Gateway。
4. 用户点击某个错误进入受影响项目或 FR 详情继续修复。
5. 修复完成后重新查看 doctor 报告，直到 Errors 为 0。

## 5. 动作定义

### 5.0 动作：创建 / 触发流水线
- 位置：FR 流水线列表页首屏主按钮
- 触发条件：用户有可选 Project，doctor Errors = 0
- 禁用条件：doctor Errors > 0、项目数据未加载、同一 Project 已有 active 流水线、终局目标缺失、提交中
- 点击后即时反馈：打开创建表单；提交后按钮 loading，表单字段锁定
- 成功结果：创建 Pipeline，生成 Stage Queue，跳转到 FR 详情页并显示当前 Stage 已开始或等待执行
- 失败结果：保留表单内容，显示明确失败原因
- 是否可撤销：提交前可关闭；提交成功后通过详情页取消 / 放弃流程处理

### 5.1 动作：点击阶段卡
- 位置：总览页真实阶段流水线卡阵
- 触发条件：阶段卡可见
- 禁用条件：无
- 点击后即时反馈：进入带阶段筛选条件的 FR 列表页
- 成功结果：列表只显示该阶段相关 FR
- 失败结果：若跳转失败，显示页面级错误态
- 是否可撤销：可，通过返回或清空筛选撤销

### 5.2 动作：切换宏阶段筛选
- 位置：FR 列表页顶部标签区
- 触发条件：列表页已加载
- 禁用条件：加载中
- 点击后即时反馈：高亮切换，列表进入重新加载态
- 成功结果：刷新为对应宏阶段的数据
- 失败结果：保留原筛选并展示错误态
- 是否可撤销：可，切回“全部阶段”

### 5.3 动作：项目筛选
- 位置：FR 列表页组合筛选条
- 触发条件：项目下拉框可用
- 禁用条件：项目数据未加载
- 点击后即时反馈：重置到第一页并刷新列表
- 成功结果：列表只显示该项目 FR
- 失败结果：保留当前选择并提示加载失败
- 是否可撤销：可，切回“全部项目”

### 5.4 动作：关键词搜索
- 位置：FR 列表页搜索框
- 触发条件：输入文字
- 禁用条件：无
- 点击后即时反馈：300ms 防抖后刷新列表
- 成功结果：标题或编号命中的 FR 被展示
- 失败结果：显示列表错误态
- 是否可撤销：可，清空输入

### 5.5 动作：展开 / 隐藏已完成
- 位置：FR 列表页筛选条右侧
- 触发条件：存在已完成 FR
- 禁用条件：无
- 点击后即时反馈：按钮文案切换，列表折叠状态变化
- 成功结果：已完成 FR 展开或再次折叠
- 失败结果：无单独失败态，沿用页面数据态
- 是否可撤销：可，再点一次

### 5.6 动作：进入 FR 详情
- 位置：FR 列表卡片、风险队列卡片、审计问题深链
- 触发条件：存在目标 FR
- 禁用条件：无
- 点击后即时反馈：页面跳转
- 成功结果：打开 FR 详情页
- 失败结果：详情页显示“没有找到这条 FR”或加载失败
- 是否可撤销：可，返回列表

### 5.7 动作：暂停
- 位置：FR 详情动作区
- 触发条件：FR 当前可暂停
- 禁用条件：动作执行中、状态不允许暂停
- 点击后即时反馈：按钮显示 spinner，其他互斥危险动作禁用
- 成功结果：FR 状态变为 paused，摘要和时间线同步更新
- 失败结果：动作区显示错误文案，保留原状态
- 是否可撤销：可，通过“恢复”撤销

### 5.8 动作：恢复
- 位置：FR 详情动作区
- 触发条件：FR 处于 paused 或可恢复状态
- 禁用条件：动作执行中、doctor Errors > 0
- 点击后即时反馈：按钮进入 loading
- 成功结果：FR 回到 active 或对应阶段继续推进
- 失败结果：显示错误文案
- 是否可撤销：可，再次暂停

### 5.9 动作：重试
- 位置：FR 详情动作区
- 触发条件：FR 失败或某阶段可重试
- 禁用条件：动作执行中、doctor Errors > 0、自动 Review Fix Loop 正在运行
- 点击后即时反馈：按钮 loading，原上下文保留
- 成功结果：尝试次数加一，当前阶段重新进入 active
- 失败结果：动作错误文案显示在当前页
- 是否可撤销：不可直接撤销

### 5.10 动作：取消 / 放弃
- 位置：FR 详情动作区
- 触发条件：FR 允许取消或放弃
- 禁用条件：动作执行中
- 点击后即时反馈：进入危险动作确认或直接 loading
- 成功结果：FR 状态更新为终止态，并在摘要区明确显示
- 失败结果：保留当前状态并提示失败原因
- 是否可撤销：默认不可撤销

### 5.11 动作：切换审计标签
- 位置：审计报告页中部标签区
- 触发条件：页面已加载
- 禁用条件：加载中
- 点击后即时反馈：标签高亮变化，内容区切换
- 成功结果：显示对应问题 / 修复 / 复验列表
- 失败结果：保留当前标签并提示错误
- 是否可撤销：可，切换回其他标签

### 5.12 动作：切换严重等级
- 位置：审计报告页筛选区
- 触发条件：页面已加载
- 禁用条件：无
- 点击后即时反馈：筛选立即生效
- 成功结果：列表只显示对应等级内容
- 失败结果：无单独失败态
- 是否可撤销：可，切回“全部”

### 5.13 动作：查看 doctor 受影响对象
- 位置：doctor 报告页错误 / 警告项中
- 触发条件：该错误关联到项目、FR 或阶段
- 禁用条件：无关联对象时不显示跳转入口
- 点击后即时反馈：跳转到受影响对象详情页
- 成功结果：用户进入具体修复上下文
- 失败结果：保留当前报告页并提示目标不存在
- 是否可撤销：可，返回 doctor 报告页

## 6. 字段与内容展示规则

### 6.1 页面状态对象契约

#### PipelineViewModel
- 来源对象：Pipeline + FR + Project + FR-18 progress
- 必显字段：`pipelineId`、`projectSlug`、`frId`、`title`、`status`、`currentStage`、`macroStage`、`endStateGoal.description`、`progress.completedStages`、`progress.totalStages`、`progress.remainingFrs`、`progress.stalled`、`progress.stalledReason`、`estimatedCompletion`
- 状态含义：Pipeline 负责整条流水线是否 created、running、blocked、stalled、completed、failed 或 canceled；页面不得把 Stage blocked 直接改写成 Pipeline failed
- 聚合规则：并行阶段有任一阻断项时 Pipeline 显示 blocked；并行阶段全部 passed 后才显示可进入下一汇合点；阶段超时但无失败结论时显示 stalled，不显示 failed
- 跳过规则：`skipped` 必须显示跳过原因、补回时机和责任阶段，不能从时间线上消失

#### StageViewModel
- 来源对象：Stage Queue + Stage Record
- 必显字段：`stageId`、`label`、`macroStage`、`status`、`requiredRole`、`parallelGroupId`、`joinCondition`、`startedAt`、`completedAt`、`attempt`、`blockers`、`artifacts`、`skipReason`
- 状态枚举：`pending / running / passed / blocked / failed / skipped`
- 并行规则：同一 `parallelGroupId` 的阶段并排展示；汇合点显示“等待哪几支通过”；只有汇合条件满足后下一阶段才进入 pending 或 running
- 回退规则：Review fail 自动回退到 Implement 时，旧 Implement 记录保留，并追加新 attempt；旧 Review 节点保留 failed / blocked 证据，新 Implement 节点显示修复轮次

#### FindingViewModel
- 来源对象：Review、Contract Review、Smoke、UX Acceptance、PM Commercial Review、Regression、Verify、Post-Release Validation 或 doctor 产生的问题记录
- 必显字段：`findingId`、`severity`、`status`、`sourceStage`、`relatedFr`、`relatedAc`、`artifactRef`、`evidence`、`suggestedFix`、`blocking`
- 状态含义：Finding 未关闭且 blocking=true 时，对应 Stage 保持 blocked；P0/P1 默认阻断，P2/P3 进入待办但不阻断当前批次，除非门禁规则显式升级
- 展示规则：Finding 的严重等级、证据和关联工件属于系统确定值，AI 摘要只能解释，不改写含义

#### FixTaskViewModel
- 来源对象：FR-06a / FR-06f / FR-17 / FR-19 自动生成的修复任务
- 必显字段：`fixTaskId`、`sourceFindingId`、`targetStage`、`status`、`priority`、`assignedRole`、`assignedAgentChanged`、`retryIndex`、`maxRetries`、`startedAt`、`completedAt`、`revalidationStatus`
- 状态含义：Fix Task 负责表达修复执行是否 queued、running、completed、failed、revalidating、closed 或 escalated；Fix Task 完成不等于 Finding 关闭，必须等定向复验通过
- Review Fix 规则：Review fail 生成的 Fix Task 必须显示“自动回退 Implement”，并显示是否已更换 Implement Agent

#### DoctorReportViewModel
- 来源对象：`sevo:doctor` 结构化报告
- 必显字段：`errors`、`warnings`、`checkedAt`、`affectedProjects`、`affectedPipelines`、`affectedStages`、`suggestedActions`
- 阻断规则：`errors > 0` 是全局推进阻断。列表页创建入口、详情页恢复 / 重试 / 推进动作、任何会触发后续阶段的操作都禁用；查看、返回、跳转修复对象、刷新报告不禁用

### 6.2 统一字段规则

#### 字段：FR 标题
- 含义：本条流水线处理的需求标题
- 数据来源：FR 实体
- 展示格式：单行优先，超长截断并保留完整详情页标题
- 是否必显：是
- 空值处理：显示“未命名 FR”
- 超长处理：列表页 40 字左右截断，详情页允许完整展示

#### 字段：FR 编号
- 含义：如 `FR-37` 的可识别编号
- 数据来源：FR 实体
- 展示格式：短标签
- 是否必显：是
- 空值处理：显示“编号缺失”并标记异常
- 超长处理：不适用

#### 字段：当前编排阶段
- 含义：真实 Stage Queue 中的当前位置，可为主阶段、子门禁、并行支路或回退修复轮次
- 数据来源：PipelineViewModel.currentStage + StageViewModel
- 展示格式：使用阶段中文名称；并行阶段显示并行组名；回退修复显示“Implement 修复第 N 轮”
- 是否必显：是
- 空值处理：显示“阶段未知”
- 超长处理：不适用

#### 字段：当前宏阶段
- 含义：4 个用户宏阶段之一
- 数据来源：`USER_MACRO_STAGE_MAP`
- 展示格式：中文标签
- 是否必显：是
- 空值处理：显示“阶段未映射”
- 超长处理：不适用

#### 字段：Pipeline 状态
- 含义：整条流水线的生命周期状态，如 created、running、blocked、stalled、completed、failed、canceled
- 数据来源：PipelineViewModel.status + PipelineProgress
- 展示格式：标签 + 中文文案；blocked 必须显示阻断 Stage 或 Finding；stalled 必须显示卡住时长和最近证据
- 是否必显：是

- 超长处理：不适用

#### 字段：Warnings
- 含义：非阻断但需要处理的数量
- 数据来源：`sevo:doctor` 结构化输出
- 展示格式：大数字 + 琥珀色提示态
- 是否必显：是
- 空值处理：显示 `0`
- 超长处理：不适用

#### 字段：建议修复动作
- 含义：用户下一步该做什么
- 数据来源：doctor 报告中的建议动作
- 展示格式：人话短句
- 是否必显：是
- 空值处理：显示“暂无建议”
- 超长处理：列表中截断，详情可完整展开

## 7. 页面状态机

### 7.1 初始态
- 触发条件：用户刚进入页面，数据请求尚未发出或刚发出
- 页面展示：页面骨架可见，内容区为空白骨架
- 可做动作：不可执行内容区动作；可返回或切导航

### 7.2 加载态
- 触发条件：正在请求数据
- 页面展示：使用 `PageSkeleton` 或局部 skeleton；不显示旧错误文案
- 可做动作：避免重复触发同一请求；允许离开页面

### 7.3 空态
- 触发条件：请求成功但当前无数据
- 页面展示：明确说清“当前为什么是空的”和“下一步可以做什么”
- 可做动作：去 FR 列表、清空筛选、展开已完成、返回上页

### 7.4 错误态
- 触发条件：请求失败或目标对象不存在
- 页面展示：标题 + 错误原因 + 重试动作
- 可做动作：重试、返回列表、切换其他页面

### 7.5 处理中
- 触发条件：FR 动作执行中、数据刷新中、审计筛选切换后加载中
- 页面展示：按钮 spinner、禁用互斥动作、保留当前页面上下文
- 可做动作：除当前互斥动作外，可浏览已加载内容

### 7.6 已完成
- 触发条件：FR completed、问题 closed、doctor Errors=0
- 页面展示：状态标签变为完成 / 通过；提供下一步查看入口
- 可做动作：查看产物、查看账本、继续看其他 FR

### 7.7 超时 / 中断
- 触发条件：长任务无响应、动作请求失败、阶段长时间停留未更新
- 页面展示：不把它伪装成“还在正常加载”；显示“卡住 / 失败 / 需恢复”文案
- 可做动作：重试、查看失败原因、进入风险与动作页

### 7.8 页面级状态细则

#### 总览页
- 无数据：提示“还没有 FR 进入系统”，主动作去 FR 流水线
- 加载失败：显示“总览加载失败”，提供重试

#### FR 列表页
- 空筛选结果：解释是筛选过窄还是都已完成
- 已完成折叠：不算空态，要额外提示“有 N 个已完成已折叠”

#### FR 详情页
- 找不到对象：显示“没有找到这条 FR”
- 动作失败：错误出现在动作区，不覆盖整页内容

#### 审计报告页
- 无评审数据：显示“暂无评审数据”，不出现空白列表
- 严重等级筛选为空：显示“当前筛选条件下没有评审问题”

#### doctor 报告页
- Errors > 0：整页进入阻断态，错误列表优先于警告列表
- Errors = 0 且 Warnings > 0：可继续推进，但要显示提醒
- Errors = 0 且 Warnings = 0：显示系统健康，通过态明确

## 8. AI 特有反馈规则

### 8.1 哪些内容是 AI 生成

- 5 秒摘要
- 风险摘要句
- 审计问题描述中的自然语言概括
- doctor 报告中的建议修复动作文案

这些内容属于对结构化状态的解释，底层状态字段仍单独展示。

### 8.2 哪些内容是系统确定值

- FR 编号
- 当前阶段
- 宏阶段映射
- pipeline 状态
- issue 严重等级
- fix task 状态
- Review / Smoke Test / UX Acceptance / PM Commercial Review / Regression / Verify / Post-Release Validation 状态
- doctor 的 Errors / Warnings 数量

系统确定值必须直接展示，不允许被 AI 文案改写含义。

### 8.3 AI 标识方式

- 所有由 AI 归纳的摘要区，都使用“摘要 / 建议 / 解释”类文案，不伪装成原始证据。
- 原始证据字段和 AI 摘要并排展示时，证据字段优先，摘要字段在下。
- doctor 页中的建议修复动作要和错误证据分区展示，避免用户把建议误当事实。

### 8.4 输入来源说明

AI 生成文案仅允许基于当前页面已有的结构化字段生成，不引入外部猜测。比如：

- 5 秒摘要来自 `fr.status`、`failedStages`、`blockingStages`、`currentStage`
- 总览页健康总结来自 `healthScore`、`blockedFrs`、`failedFrs`、`riskCount`
- doctor 建议来自本次 `sevo:doctor` 报告中的错误和警告项

### 8.5 不确定性提示

当 AI 只能给出概括，不能给出确定根因时，文案必须收敛为“先去哪里看”，不能冒充结论。比如：

- 可以说“先把红灯灭掉”
- 不能说“失败原因就是代码错误”，除非系统字段已明确给出

### 8.6 重试方式

- 摘要类 AI 文案不提供单独“重生成”按钮，避免引入额外噪音。
- 用户刷新页面时，AI 摘要随底层数据一起更新。
- 如果结构化数据缺失，则降级显示原始字段，不强行生成摘要。

### 8.7 覆盖 / 保留策略

- 新摘要覆盖旧摘要，但不覆盖原始状态字段。
- 动作失败后的错误文案优先保留，直到用户下一次动作或页面刷新。
- doctor 报告必须始终以本次最新检查结果覆盖旧结果，防止用户误读历史状态。

## 9. 长任务与异步可见性

### 9.1 真实编排阶段模型

SEVO Web 的时间线以 spec 中的真实 Stage Queue 为准，不能把阶段压缩成固定 11 项。页面同时提供两层视图：

- 编排真实阶段层：完整展示 Pipeline Create、业务阶段、子门禁、并行阶段、回退链路、终局交付链。
- 用户聚合视图层：把真实阶段折叠到 4 个用户宏阶段，供列表筛选和总览统计使用。

#### 真实阶段顺序与关系

1. Pipeline Create：创建 Pipeline，生成 Stage Queue，写入终局目标和进度摘要。
2. Spec：产出需求规格包。
3. Mandatory Spec Sections Pre-Gate：Spec Review Gate 前置硬门禁，失败时回到 Spec。
4. Spec Review Gate：产品、技术、质量、体验维度评审；涉及 Web/UI 时体验维度必显。
5. Spec Review 通过后的并行组：Test Case Authoring、UX Acceptance Authoring、Commercial Acceptance Authoring、UX Interaction Design（按路由触发）、Architecture Design（按路由触发）、Contract。并行阶段各自显示状态，全部必需输入满足后进入 Contract Review Gate。
6. Contract Review Gate：产品、开发、质量、体验四方会审；任一方阻断时进入 Review Fix Loop，修复后回本门禁复验。
7. Implement：执行实现；Systematic Debugging 作为 Implement 内部可选活动显示在 Implement 展开层。
8. Review：PM/产品、质量、SA/架构三方独立评审，内含 spec-code 覆盖、Tiered Scan、部署视图等门禁。
9. Review Fix Loop：Review fail 或 conditional pass 且存在阻断 Finding 时，自动回退 Implement → 修复 → 重新 Review；默认最多 2 轮，且每轮必须换不同 Implement Agent；超限后停在 Review Fix 状态。
10. Smoke Test：Review PASS 后自动触发。
11. UX Acceptance + PM Commercial Review：Smoke Test 通过后并行执行，两者均 passed 后进入 Regression。
12. Regression：回归检查。
13. Commercialization Gate：存在 publishTarget 时，在 Deploy 前自动触发；不存在时该阶段不出现。
14. Deploy：生成发布制品，并按发布目标执行发布前动作。
15. Verify：独立环境验证。
16. README Update：终局交付链中检测 README 是否反映本次变化，缺失时自动生成更新任务；已满足时显示 skipped 和原因。
17. Version Bump：根据变更类型自动判定 patch / minor / major，已关闭自动版本管理时显示 skipped 和原因。
18. Publish：执行发布；失败自动重试一次，仍失败则 Pipeline blocked。
19. Post-Release Validation：发布后终局差距扫描；发现差距时生成 Fix Task，并回到 Implement → Review → 终局交付链继续收敛。
20. Ledger：全部必需阶段完成、剩余 FR 为 0、终局差距扫描通过后写入交付账本。

#### 宏阶段映射

- 需求澄清：Pipeline Create、Spec、Mandatory Spec Sections Pre-Gate、Spec Review Gate。
- 方案规划：Test Case Authoring、UX Acceptance Authoring、Commercial Acceptance Authoring、UX Interaction Design、Architecture Design、Contract、Contract Review Gate。
- 执行落地：Implement、Systematic Debugging、Review fail 后自动回退产生的 Implement 修复轮次、Deploy、README Update、Version Bump、Publish。
- 质量复核：Review、Review Fix Loop、Smoke Test、UX Acceptance、PM Commercial Review、Regression、Commercialization Gate、Verify、Post-Release Validation、Ledger。

#### 并行、汇合与回退显示规则

- 并行组必须并排展示，不把多个阶段压成一个“进行中”。
- 汇合点必须显示“已通过几支、还在等哪几支”。
- 回退不覆盖历史节点，使用新 attempt 追加到时间线。
- Review fail 的强制路径是 Review → Implement 修复 → Review 复验 → 后续阶段。
- Post-Release Validation 发现差距时，显示差距 Fix Task，并回到 Implement → Review → 终局交付链。
- skipped 阶段必须显示原因、补回时机和责任阶段；最终 completed 前未补回的必需阶段要阻断完成。

### 9.2 列表页显示规则

- 列表页显示当前宏阶段和当前编排阶段。
- 如果 FR 失败，列表卡片直接标红并显示“失败待处理”。
- 如果 FR 暂停，显示等待态，不要继续伪装为进行中。
- 已完成默认折叠，避免长任务历史淹没当前任务。

### 9.3 详情页显示规则

- 详情页必须显示完整阶段时间线。
- 当前阶段突出显示。
- 已通过阶段显示通过态和完成时间。
- 失败或阻塞阶段必须显示原因或 blocker 列表。
- 重试后 attempt 数要变化，用户能看见这已经进入新的执行轮次。

### 9.4 是否可离开页面

- 可以离开。
- 用户离开后，流水线仍在后台继续推进。
- 页面不能要求用户“盯着等”。

### 9.5 返回后恢复方式

- 用户重新进入总览页，看健康摘要和风险数量是否变化。
- 用户重新进入 FR 详情页，看当前阶段是否推进、attempt 是否增加、失败是否转通过。
- 审计页返回后，问题、修复、复验列表按最新状态刷新。
- doctor 页返回后，以最近一次检查结果覆盖旧报告。

### 9.6 完成通知

- 总览中的失败待恢复、门禁等待、正在推进统计要随着数据更新变化。
- 风险队列中的动作项处理后应消失或降级。
- 审计问题关闭后，复验通过率同步变化。
- doctor Errors 清零后，阻断提示消失并切换为通过态。

### 9.7 失败恢复入口

- FR 失败：在详情页动作区给出重试或恢复入口。
- 门禁等待：在风险与动作页或相关 gate 页给出审批入口。
- 审计问题：在审计报告页定位修复任务。
- doctor 错误：在 doctor 报告页跳转受影响对象继续修复。

## 10. 生成过程可见

### 10.1 总体规则

SEVO 是长任务产品，不能只给一个 loading。用户必须看见“请求已收到、现在跑到哪、还要不要我介入”。

### 10.2 在总览页的体现

- 健康摘要不能只给一个 loading。加载完成后立刻用一句话说明当前局面。
- 风险队列 Top 3 让用户知道当前系统已经为他挑出最该处理的动作。

### 10.3 在 FR 详情页的体现

- 当前阶段、已耗时、attempt、时间线共同构成生成过程可见性。
- 如果阶段还在跑，状态必须明确是“进行中”，不能只有灰色静态页面。
- 如果阶段失败，用户应立刻看到失败发生在哪一步。

### 10.4 在审计报告页的体现

- 问题 → 修复 → 复验三视角并列，就是审计闭环的可视化过程。
- 用户切到“修复任务”或“复验结果”时，必须能直接看见问题没有停在发现阶段。

### 10.5 在 doctor 报告页的体现

- 报告顶部先显示本次检查结论和时间。
- Errors / Warnings 数量必须在首屏。
- 诊断页的核心是“当前诊断结论已经足够明确”，过程动画只作为辅助。

## 11. 不确定性可见

### 11.1 必须可见的不确定性

- AI 摘要只是概括，不等于原始证据。
- 阶段失败并不天然等于根因已明，用户可能还需要点进详情或修复对象。
- doctor 的建议修复动作是方向，不等于系统已经修好。

### 11.2 页面表达方式

- 摘要区用“当前判断”“下一步建议”语气，不用“最终原因”语气。
- 问题列表保留严重等级、状态、阶段等结构化字段，让用户自己复核。
- doctor 报告中的证据摘要和建议动作分开摆放。

### 11.3 用户可怎么继续确认

- 从总览跳到 FR 列表
- 从 FR 列表跳到 FR 详情
- 从详情跳到质量视图、时间线、审计页
- 从 doctor 错误项跳到受影响项目或 FR

页面要把这些确认路径做成可点击动作，别把用户留在一句模糊摘要里。

## 12. 异步任务可恢复

### 12.1 恢复原则

用户随时可以离开，再回来接着看。系统不能依赖用户持续驻留页面。

### 12.2 FR 恢复

- FR 详情页的时间线是主恢复载体。
- 返回详情后，用户能看到当前跑到哪一阶段、是否失败、是否被阻塞、是否重试过。
- 暂停态和失败态都必须给出明确恢复入口。

### 12.3 审计恢复

- 审计报告页重新进入后，问题、修复、复验三类状态必须连续。
- 已关闭问题不应继续混在待处理问题里。
- 复验失败的问题要重新显性回到待处理链路。

### 12.4 doctor 恢复

- doctor 报告再次打开时，应显示最新一次检查结果，不能继续展示陈旧缓存。
- 如果上一次有 Errors，本次已清零，用户要在首屏看见状态切换。

### 12.5 刷新恢复

- 手动刷新页面后，不丢筛选条件和当前对象上下文。
- 列表页保留搜索、阶段、项目筛选。
- 详情页保留当前 FR 上下文。

## 13. 混合交互模式要声明分工

### 13.1 结构化交互负责什么

- 列表筛选
- 项目筛选
- 状态切换
- 审计标签切换
- 危险动作执行
- doctor 错误定位

这些都必须用明确按钮、标签、卡片完成，不交给自然语言输入。

### 13.2 AI 解释负责什么

- 用人话解释当前 FR 状态
- 用一句话总结总览健康情况
- 用建议语气解释 doctor 报告中的优先处理方向

AI 的职责是解释，不负责替代结构化操作。

### 13.3 页面分工边界

- 总览页负责判断优先级，不负责处理复杂细节。
- FR 列表页负责定位目标，不负责展示全量阶段细节。
- FR 详情页负责理解单条 FR 上下文并执行主动作。
- 质量视图负责展开 Review、Smoke Test、UX Acceptance、PM Commercial Review、Regression、Verify、Post-Release Validation 等质量信息。
- 审计报告页负责围绕问题闭环处理。
- doctor 报告页负责系统层阻断判断。

### 13.4 视觉硬约束

所有页面统一采用白色底、黑色字主调：

- 页面背景：白色或接近白色
- 主文字：黑色或深灰黑
- 状态色只用于强调，不可反转为深色背景主界面
- doctor 阻断态可以用红色强调，但仍然保持白底黑字阅读基础

### 13.5 文案约束

- 文案优先讲“现在是什么状态、为什么、下一步去哪”
- 避免抽象术语堆叠
- 危险动作文案必须直接，如“重试”“恢复”“取消”“放弃”
- 空态文案必须包含：当前状态、为什么是空的、下一步是什么

### 13.6 开发落地约束

- Implement 阶段引用本交互文档时，必须按页面分区、动作定义、状态机和异步可见性实现。
- 不得把本文定义的阻塞态、失败态、doctor 阻断态降级为普通提示。
- 不得扩展 spec 未定义的新页面目标或新操作流。
